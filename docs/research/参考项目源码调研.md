## 2. CCR 关键发现

### 2.1 架构演进：从“场景路由 + transformer 链”到“规则引擎 + 外部协议网关”

**v2（经典设计，社区教程大多基于它）**

- 场景路由硬编码在 `getUseModel` 中，按优先级依次判断：显式 `provider,model` → 长上下文（`longContextThreshold` 默认 60000 token，或上一轮 usage 超阈值）→ `<CCR-SUBAGENT-MODEL>` 标签指定子 agent 模型 → 模型名带 `claude` 和 `haiku` 时走 `background` → 请求 tools 里有 `web_search*` 时走 `webSearch` → 请求带 `thinking` 时走 `think` → `default`。见 [v2 router.ts#L124-L200](https://github.com/musistudio/claude-code-router/blob/b1e057f9f25abd42088baa81af46f794c7ddd561/packages/core/src/utils/router.ts#L124-L200)。
- 会话 ID 从 `metadata.user_id` 的 `_session_` 后缀解析，可以按项目或会话覆盖 Router 配置，见同文件 [#L215-L225](https://github.com/musistudio/claude-code-router/blob/b1e057f9f25abd42088baa81af46f794c7ddd561/packages/core/src/utils/router.ts#L218-L226)。
- Transformer 接口分四个钩子：`transformRequestOut`（入站格式 → 统一格式）、`transformRequestIn`（统一格式 → 供应商格式）、`transformResponseOut`、`transformResponseIn`，另有 `endPoint` 和 `auth`。见 [v2 types/transformer.ts](https://github.com/musistudio/claude-code-router/blob/b1e057f9f25abd42088baa81af46f794c7ddd561/packages/core/src/types/transformer.ts)。
- 内置 transformer 共 21 个、约 4.7k 行，其中能看出“国产模型补丁”的典型做法有：
  - `deepseek`：把 `max_tokens` 硬截到 8192，并把流里的 `reasoning_content` 转成 thinking。见 [deepseek.transformer.ts](https://github.com/musistudio/claude-code-router/blob/b1e057f9f25abd42088baa81af46f794c7ddd561/packages/core/src/transformer/deepseek.transformer.ts)。截断值是写死的，模型升级后容易失效。
  - `tooluse`：注入 system-reminder，强制 `tool_choice: required`，再追加一个虚拟 `ExitTool`，以此逼模型调用工具。见 [tooluse.transformer.ts](https://github.com/musistudio/claude-code-router/blob/b1e057f9f25abd42088baa81af46f794c7ddd561/packages/core/src/transformer/tooluse.transformer.ts)。这种做法会改动提示词和工具集合，有副作用。
  - `cleancache`：删除所有 `cache_control`。见 [cleancache.transformer.ts](https://github.com/musistudio/claude-code-router/blob/b1e057f9f25abd42088baa81af46f794c7ddd561/packages/core/src/transformer/cleancache.transformer.ts)。
  - 另有 `enhancetool`、`reasoning`、`forcereasoning`、`maxtoken`、`sampling`、`customparams` 等。

**v3（当前 main）**

- 协议转换（Anthropic / OpenAI Chat / Responses / Gemini 互转、SSE 转换、熔断、并发、幂等）下沉到外部包 `@the-next-ai/ai-gateway`，CCR core 的依赖声明见 [packages/core/package.json](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/package.json)。这个包在 npm 上只有编译产物，**协议转换的核心代码无法直接审阅**，这是自研的主要理由之一。
- 路由从固定场景改成通用规则：规则类型有 `condition` / `model-prefix` / `script`，支持 `contains-deep` 等运算符、请求体 rewrite，以及每条规则单独的 fallback（`off` / `retry` / `model-chain`）。见 [contracts/app.ts#L671-L760](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/contracts/app.ts#L671-L760)。脚本规则跑在独立 worker 中，默认超时 2s，见 [routing/route-script-worker.ts](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/routing/route-script-worker.ts)。
- 失败分类很简单：429 记为 rate-limit，408/409 记为 retryable，5xx 记为 server，其余为 client。见 [routing/failure-classifier.ts](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/routing/failure-classifier.ts)。
- token 估算是启发式的：ASCII 词数加 CJK 字数，再乘 1.15，不调用 tokenizer。见 [routing/token-estimator.ts](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/routing/token-estimator.ts)。
- `/v1/messages/count_tokens` 在本地处理，返回 `plugin.countTokens(body)` 的估算值，不转发上游。见 [gateway/http/request-handler.ts#L266-L287](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/gateway/http/request-handler.ts#L266-L287)。
- 代码规模：core + cli + electron 的非测试 TS 约 11.7 万行，功能面很大（Codex / OpenCode / Kimi / Grok 本地 agent 接管、Electron 桌面、内置浏览器、插件市场、bot gateway、用量与计费库……）。

### 2.2 对 Claude Code（cc）的接入方式

- 环境变量注入：`ANTHROPIC_BASE_URL`、`ANTHROPIC_MODEL`，以及 `ANTHROPIC_DEFAULT_{FABLE,OPUS,SONNET,HAIKU}_MODEL` 和旧版 `ANTHROPIC_SMALL_FAST_MODEL`。见 [agents/claude-code/environment.ts#L1-L20](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/agents/claude-code/environment.ts#L1-L20)。
- 认证：默认写入 settings.json 的 `apiKeyHelper` 指向一个脚本，也支持 `wif`（workload identity federation）模式。见 [agents/claude-code/auth-mode.ts](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/agents/claude-code/auth-mode.ts) 和 [profiles/service.ts#L1270-L1276](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/profiles/service.ts#L1270-L1276)。
- 网关还实现了 `GET /api/claude_cli/bootstrap` 和 `POST /v1/oauth/token`，用来应付 cc 启动时的引导请求，见 request-handler.ts 中的 endpoints 列表（同上文件 #L242）。

### 2.3 对 Claude 桌面版的接入方式

- 写入桌面端 `configLibrary/<id>.json`，内容为 `inferenceProvider: "gateway"`、`inferenceGatewayBaseUrl`、`inferenceGatewayApiKey`（认证方式 `x-api-key`）、`inferenceModels[]`（可带 `supports1m`）、`modelDiscoveryEnabled: true`，同时修改 `_meta.json` 的 appliedId。见 [agents/claude-app/gateway-service.ts#L150-L175](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/agents/claude-app/gateway-service.ts#L150-L175)。
- 桌面端模型 ID 会被编码成 `anthropic/claude-ccr-h…` 这类前缀，用 `[1m]` 后缀表示 1M 上下文，再在网关侧映射回真实 provider/model。见 [agents/claude-app/gateway-routes.ts](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/agents/claude-app/gateway-routes.ts)。
- 风险：自动应用会切换桌面端当前生效的配置，不会继承用户 Default 配置里的浏览器、出网等字段。

### 2.5 v3 中值得借鉴的细节

- **多 key 池**：每个 credential 可配置 `priority` / `weight` / `limits`（窗口限额）；遇到 401、403、429 时冷却 60s。见 [providers/credential-pool.ts](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/providers/credential-pool.ts)。

- **thinking 合并**：非流式时，把相邻的无签名 thinking 块合并成一个；带签名的块不合并，否则签名会失效。见 [gateway/features/anthropic-reasoning-response.ts](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/gateway/features/anthropic-reasoning-response.ts)。
- **DeepSeek 缓存用量归一**：把 `prompt_cache_hit_tokens` 转成 `prompt_tokens_details.cached_tokens`，见 [gateway/features/opencode-cache-usage.ts](https://github.com/musistudio/claude-code-router/blob/057abaa1f95519ab8faf999e1ccef2b80ccdeb9e/packages/core/src/gateway/features/opencode-cache-usage.ts)。

## 3. dsh 关键发现

### 3.1 定位

dsh 是一个 agent harness（运行时 + 客户端 + 插件体系），**不是对外提供 `/v1/messages` 的网关**。它的 `api-gateway` 是客户端到 harness 后端的 RPC 网关。对我们有价值的是它在**出站侧**处理国产模型差异的方式。

### 3.2 DeepSeek 直连适配器 `llm-deepseek`

- 走 DeepSeek 官方 **Anthropic Messages** 端点，而不是 OpenAI 格式。请求头固定 `anthropic-version: 2023-06-01`，按需追加 `anthropic-beta`（Files、tool changes），`redirect: 'error'`，并带 `x-deepseek-harness-*` 自定义头。见 [llm-deepseek/src/adapter.ts#L131-L150](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/llm/llm-deepseek/src/adapter.ts#L131-L150)。
- 序列化时严格校验 tool_use / tool_result 配对：结果缺失、多余或悬空都直接报 `INVALID_REQUEST`，不静默修补。thinking 由 effort 推导，取值 `off|low|high|max`，映射为 `thinking.type` 和 `output_config.effort`。见 [serialize.ts#L130-L170](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/llm/llm-deepseek/src/serialize.ts#L130-L170)。
- **thinking 签名回放**：签名按模型校验，跨模型的签名不可移植，遇到时降级丢弃并上报诊断，诊断里不含正文。见 [replay.ts#L30-L45](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/llm/llm-deepseek/src/replay.ts#L30-L45)。这一点直接关系到网关里“同一会话中途切换模型”的处理。
- 用量映射：`cache_read_input_tokens` / `cache_creation_input_tokens` 原样保留。见 [translate.ts#L36](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/llm/llm-deepseek/src/translate.ts#L36)。
- 错误分类：401/403 记为 AUTH，额度耗尽或 402 记为 QUOTA，429 记为 RATE_LIMIT，5xx 或 `overloaded_error` 记为 SERVER，另有专门的上下文超限识别。见 [transport.ts#L20-L40](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/llm/llm-deepseek/src/transport.ts#L20-L40)。
- 默认上下文窗口为 1,000,000，可按模型覆盖。见 [defaults.ts#L6](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/llm/llm-deepseek/src/defaults.ts#L6)。
- 图片：模型未声明 `inputModalities` 包含 image 时直接报 `UNSUPPORTED_CONTENT`，不静默丢图。见 [images.ts#L40-L50](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/llm/llm-deepseek/src/images.ts#L40-L50)。另外优先走 Files API 上传换 file_id，失败时退回 inline base64（adapter.ts 同段）。

### 3.3 多供应商适配器 `llm-pi-ai`：用 compat 开关描述国产模型差异

dsh 没有给每家写一个 transformer，而是把差异抽象成一组**声明式 compat 字段**（由 pi-ai 定义，dsh 用“drift gate”把每个字段标为 offer 或 withhold）：

- OpenAI Chat 兼容侧的字段：`thinkingFormat`（`deepseek` / `zai` / `qwen` / `qwen-chat-template` / `openrouter` …）、`requiresReasoningContentOnAssistantMessages`、`requiresThinkingAsText`、`requiresToolResultName`、`requiresAssistantAfterToolResult`、`maxTokensField`（`max_tokens` 或 `max_completion_tokens`）、`supportsDeveloperRole`、`supportsReasoningEffort`、`supportsUsageInStreaming`、`cacheControlFormat`、`supportsStrictMode`、`zaiToolStream`（dsh 将其设为 withhold）等。见 [llm-pi-ai/src/catalog.ts#L85-L140](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/llm/llm-pi-ai/src/catalog.ts#L85-L140) 与 [#L245-L300](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/llm/llm-pi-ai/src/catalog.ts#L245-L300)。
- Anthropic 兼容侧的字段：`supportsEagerToolInputStreaming`、`supportsCacheControlOnTools`、`supportsTemperature`、`forceAdaptiveThinking`、`allowEmptySignature`、`supportsLongCacheRetention`（同文件 ANTHROPIC_COMPAT_GATE）。
- pi-ai 按 provider 名或 baseURL 自动探测默认值，用户配置可以逐项覆盖（npm `@earendil-works/pi-ai@1.4.0` 的 `dist/api/openai-completions.js` 中 `detectCompat` / `getCompat`）。从中能看到的具体差异：
  - DeepSeek：`thinkingFormat=deepseek`（请求里写 `thinking: {type: enabled}`）；回放 assistant 消息时**必须带 `reasoning_content`**，缺失就补空字符串；使用 `max_tokens` 字段；不支持 `store` 和 developer role。
  - 智谱（`open.bigmodel.cn` / `api.z.ai`）：`thinkingFormat=zai`，写 `thinking: {type: enabled, clear_thinking: false}`；不支持 `reasoning_effort`；可选 `tool_stream: true`。
  - Qwen：`thinkingFormat=qwen`，写 `enable_thinking`。
  - Moonshot：不支持 `reasoning_effort`，使用 `max_tokens`。
  - 带工具历史但本轮没有工具时，补发 `tools: []`，因为部分代理要求这样。
- 内置端点目录（[provider-data.generated.ts](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/llm/llm-pi-ai/src/provider-data.generated.ts)）：`zai-coding-cn`、`kimi-coding`、`moonshotai-cn`、`minimax-cn`（Anthropic 端点 `api.minimaxi.com/anthropic`）、`qwen-token-plan-cn`、`xiaomi-token-plan-cn` 等。各家的 coding / token plan 端点都单列出来。
- OAuth：pi-ai 支持 Anthropic OAuth token。用 OAuth 时会注入 `claude-code-20250219,oauth-2025-04-20` beta、`claude-cli` UA，以及“You are Claude Code…”system 前缀（pi-ai `dist/api/anthropic-messages.js`，约 L810–L935）。dsh 的 [login.ts#L20-L26](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/llm/llm-pi-ai/src/login.ts#L20-L26) 明确不提供部分 OAuth 登录。订阅 OAuth 直通本期不做，见方案文档 §6.1。

### 3.4 web 能力与多模态

- web 能力分三层：`ctx.web` 服务层统一搜索和抓取接口，可插拔后端有 Exa、Perplexity、DeepSeek（借 Messages 的 `web_search_20250305` server tool）、DeepSeek Search/Fetch API 和匿名 HTTP fetch，再由 `tool-web` 暴露 `web_search` 和 `web_fetch` 两个模型工具。见 [packages/web/README.zh.md](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/web/README.zh.md)。
- DeepSeek 搜索后端：每次搜索消耗一轮模型调用；如果返回中没有结构化结果块，就当作错误，不从正文里抓取。见 [web-search-deepseek/src/provider.ts](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/web/web-search-deepseek/src/provider.ts)。
- HTTP fetch 手动跟随重定向（`redirect: 'manual'`），便于逐跳做网络策略检查。见 [web-fetch-http/src/provider.ts](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/web/web-fetch-http/src/provider.ts)。
- 图片超出预算时，`compaction-image-offload` 把较早的图片永久替换成“附件 + 只读路径”的文本，并说明缓存只能复用到第一条被改写的消息之前。见 [compaction-image-offload/README.zh.md](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/compaction/compaction-image-offload/README.zh.md)。

## 4. 小结：两者各自解决了什么、没解决什么

| 维度 | CCR v3 | dsh |
|---|---|---|
| 对 cc / 桌面版的入站兼容 | 完整：环境变量、apiKeyHelper、桌面 configLibrary、bootstrap 端点 | 没有（不是入站网关） |
| 协议转换的可审计性 | 核心在闭源编译包里，难以审阅 | 出站转换代码清晰，有严格校验 |
| 国产模型差异 | 预设只到端点 / 协议层；v2 的 transformer 是写死的补丁 | 声明式 compat 开关，粒度细，可逐项覆盖 |
| thinking 签名 / 跨模型 | 合并无签名块，保护签名块 | 按模型校验签名，跨模型降级丢弃 |
| 缓存 | 归一 DeepSeek 缓存字段；v2 还有 cleancache | 原样映射 Anthropic 缓存 usage |
| 多 key / 额度 | 有 key 池、冷却和额度连接器 | 凭据按请求解析，支持 OAuth 刷新和跨进程锁 |
| 搜索 / 抓取 / 视觉 | 网关内托管 web search 改写 + MCP 视觉工具 | 作为 agent 工具（web_search / web_fetch），不在网关层 |
| 体量 | 约 11.7 万行，功能面很大 | 整体是完整 harness，相关包每个几千行 |
